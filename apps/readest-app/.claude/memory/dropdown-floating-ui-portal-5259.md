The #5410 fix (all in-DOM, menu stays adjacent to its toggle): MenuItem labels wrap (`break-words text-pretty text-start`, rows `min-h-*` not `h-*`); `:where(.dropdown-content){width:max-content;max-width:calc(100vw - 32px)}` — `:where` keeps utility widths (w-44, max-w-[90vw]) winning, and `width:max-content` is REQUIRED because enabling wrap collapses the anchor-positioned shrink-to-fit box toward its longest word (CJK = one char; the old code accidentally got its width from `truncate`'s nowrap); Dropdown measures the open menu (`details > :not(summary)`) in useLayoutEffect and translateX-clamps it into the viewport (16px padding, re-clamp on resize + ResizeObserver); Overlay is `aria-hidden` (it was an unlabeled full-screen clickable node in the TalkBack traversal path); `<summary aria-hidden>` got `tabIndex={-1}`. Regression tests: `dropdown-viewport.browser.test.tsx` incl. a DOM-adjacency guard. Verified on Xiaomi 13 + TalkBack: first entry immediately follows the toggle in the a11y tree, overlay node gone, no auto-dismiss, menus fit the 392px viewport.

Rejected PR #5392 architecture notes (kept for context):

- Dropdown now uses `@floating-ui/react-dom` (pinned exact `2.1.8`), `strategy: 'fixed'`, middleware `flip` + `shift` + `size` with 16px viewport padding. The `size` middleware exposes `--dropdown-available-width` consumed by `.dropdown-positioner` max-width in globals.css.
- Menu + Overlay render via `createPortal` into `element.closest('.modal') ?? document.body` — portaling into the nearest `.modal` preserves modal stacking (Overlay z-40, positioner z-50). The old `<details class="dropdown">`/`<summary>` daisyUI markup is gone.
- New `align` prop (`'start' | 'center' | 'end'` → `bottom-start`/`bottom`/`bottom-end`) replaces `dropdown-bottom/dropdown-center/dropdown-end` classes at every call site; `.dropdown-center` CSS and the `.ui-rtl` inset overrides were deleted. RTL works because `.ui-rtl .dropdown-positioner { direction: rtl }` makes Floating UI's logical start/end flip automatically.
- `Menu.tsx` now nests `.menu-clip` (overflow hidden, `border-radius: inherit` — clips scrollbar inside rounded corners) + `.menu-scroll` (scrolling + 10px padding, `max-h-[calc(100vh-96px)]`, overridable via new `scrollClassName` prop). `.dropdown-content.menu-container` gets `padding: 0` — padding passed on Menu `className` is dead there; use `scrollClassName` (e.g. `!p-2`).
- `MenuItem` labels changed from `truncate` to `break-words text-pretty text-start` — long labels wrap and rows grow, so fixed `h-8` rows became `min-h-8 !py-1` (library ViewMenu). Any new menu row must use min-h, not h.
- Browser test `src/__tests__/components/dropdown-layout.browser.test.tsx` guards viewport containment, label wrap, CJK natural width, RTL, explicit `w-44` width, anchor-move reposition, and menu-clip corner clipping.
- Bundled commit: `suppressHydrationWarning` on `<html>` in `src/app/layout.tsx` (browser extensions inject attrs pre-hydration).

A11y: static checks passed but REAL SCREEN READERS BROKE — the CDP/axe pass was misleading. First pass (2026-07-31, desktop Chrome dev vs dev~3 baseline + Xiaomi CDP): axe scans identical before/after, ARIA state intact, menuitems in Blink AX tree with ON/OFF state, viewport fit verified on 392px. But chrox then reported VoiceOver AND TalkBack cannot focus menu entries — CONFIRMED on Xiaomi 13 with TalkBack actually running: (1) entries sit LAST in traversal order (portal at body end) instead of adjacent to the toggle — 20+ swipes away; (2) the Overlay is an UNLABELED full-screen clickable node right before them whose activation dismisses; (3) background stays fully focusable; (4) menu intermittently AUTO-DISMISSES ~0.5s after opening when TalkBack a11y focus sits on background content; (5) explore-taps on entries got swallowed or dismissed the menu. Fix validated live on-device: DOM-`focus()` the first enabled menu item on open → TalkBack green rect lands on the entry and the menu stays stable (also fixes keyboard Tab adjacency; VoiceOver follows DOM focus the same way). Full fix = focus-first-item-on-open + `aria-hidden` on Overlay + ideally role='menu' container. LESSON: Blink AX tree / axe / `Accessibility.getFullAXTree` do NOT verify screen-reader NAVIGATION — traversal order, hover interception, and focus-recovery behavior only show up with the service on. `uiautomator dump` includes web nodes ONLY while an a11y service is connected; TalkBack intercepts injected `input tap` inconsistently (explore vs pass-through), so verify via dump + `focus()` + screencap of the green focus rect, not taps. Escape-from-toggle keeps focus; Escape-while-other-toggle-focused is swallowed by stopPropagation (pre-existing).

**Why:** future dropdown/menu work must target the positioner model — no more absolute-position CSS hacks (`!relative`, `left-0`, inline `maxWidth: window.innerWidth` styles were all removed).
**How to apply:** new Dropdown call sites: use `align` + `containerClassName`; `className` lands on the portaled `.dropdown-positioner`, NOT an in-flow element.
