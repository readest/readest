**#5808** (Android, 0.12.1): rotate portrait->landscape->portrait and the reader skips back a page; each further rotation repeats it. Reporter: "usually reproducible at the start of a section, usually in two-column layout." Same drift hits any resize round trip (desktop window resize, tablet split view); rotation just makes it symmetric.

**Root cause (foliate `packages/foliate-js/paginator.js`):** a resize re-render restores the anchor via `render()` -> `#scrollToAnchor(#anchor)` (reason `'anchor'`), which correctly keeps `#anchor`. But the scroll that restore performs also reaches the debounced `#container` scroll listener, which in paginated mode calls `#afterScroll('container-scroll')` and UNCONDITIONALLY replaced `#anchor` with the reflowed layout's visible range. That range starts at the new page's first char, which precedes the old anchor whenever the two layouts' page boundaries differ (almost always) -> next resize back settles one page earlier, and it walks back every cycle. The scrolled-mode branch already guards this with `#justAnchored`; the paginated branch had none. `container-scroll` + `localPage===0` early-returns (added by 7657c78 a11y commit) so it doesn't *dispatch* relocate, but the `this.#anchor = range` assignment happens BEFORE that return — that's the poison.

**Fix (fork branch `fix/resize-anchor-drift` off e994c18, commit 1079e3b):** in `#afterScroll`, a `container-scroll` relocate keeps `#anchor` when the current Range anchor still starts inside the new visible range (new helper `#anchorIsVisible(range)` using `range.comparePoint`, guarded for cross-doc/torn-down nodes and IndexSizeError). Restructured the guard to `if (selection|navigation|anchor) justAnchored=true; else if (reason!=='container-scroll' || !anchorIsVisible) #anchor=range`. Fraction/element anchors and off-page scrolls behave as before. NOT a one-shot flag (a `#justAnchored`-style latch would leak if an anchor scroll produced no scroll event).
