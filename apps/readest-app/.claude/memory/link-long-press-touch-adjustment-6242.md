**Link half — MERGED #6248 (8fd2d53b0), 2026-09-18.** Chromium's touch adjustment retargets an Android long press onto any `a[href]` within ~12–17 CSS px of the finger (even with a zero-size adb touch), and a link long press never starts a selection. NOT tablet-specific — reproduced at phone size too. Fix: `html.link-touch-hold a[href]{pointer-events:none!important}` (style.ts page layout styles), class added on touch `pointerdown` (Android app only) and removed on `pointerup`/`pointercancel` in useTextSelector. pointerup runs before the tap gesture resolves its target, so taps still follow links. Device-verified on Xiaomi (WebView 153) with the real build. A JS "select word at pointerdown on contextmenu" prototype also worked but gives NO handles (engine draws native grabbers only for user-initiated selections) — rejected.
