Reported 2026-08-25 (Lenovo Tab P11 Pro Gen 2, Android 14, Readest 0.12.1, plus the reporter's phone): the app dies immediately at launch with `java.lang.IllegalArgumentException: width must be > 0` at `Bitmap.createBitmap`, obfuscated frames `X.Y.i(SourceFile:185)` / `Z.e.f(SourceFile:8)` / `DispatchedTask.run(:113)`, suppressed `DiagnosticCoroutineContextException [StandaloneCoroutine{Cancelling}, Dispatchers.Main]`.

**Root cause:** `ReadingWidgetStore.writeThumbnail` (android native-bridge plugin) center-crops covers to 2:3 with `cropW = srcH * 2 / 3`; a cover that decodes 1px tall (1x1 placeholder cover shipped in some EPUBs, or a wide banner that `inSampleSize` downsamples to one row) gives `cropW = 0` and the crop overload of `createBitmap` throws. The call sits in `pluginScope.launch { withContext(IO) {...} }` (SupervisorJob + Dispatchers.Main, no CoroutineExceptionHandler), so the exception is uncaught and fatal. `useReadingWidget` republishes the snapshot on every library load, hence a crash on EVERY launch, and `writeThumbnail` runs even when no widget is placed. Present since the widget shipped in 0.11.20 (#4842); iOS unaffected (its writer only scales, no crop).

**How it was pinned:** the trace has exactly two nested `createBitmap` frames before `checkWidthHeight`, which is the `(source, x, y, w, h)` crop overload; the `(w, h, config)` overload has four. Only two `createBitmap` call sites exist in our Kotlin. Reproduced on the Xiaomi against the installed 0.12.1 build by invoking `plugin:native-bridge|update_reading_widget` over CDP with `coverPath` pointing at a 1x1 PNG in /sdcard/Download: identical crash, identical frame line numbers (185/8/113).

**Fix (worktree `fix/widget-thumbnail-degenerate-cover`):** guard `srcW < 2 || srcH < 2` in `writeThumbnail` (recycle, delete stale thumbnail, return) + per-book try/catch with `Log.w` around `writeThumbnail` in `update_reading_widget` so no thumbnail failure can ever escape pluginScope again. Instrumented regression test `writeThumbnail_1x1Cover_doesNotCrashAndDropsStaleThumbnail` in `ReadingWidgetStoreTest.kt` (fails pre-fix, passes post-fix on the Xiaomi).

- When the Xiaomi is locked, run the instrumented suite on the emulator instead: `emulator -avd Android15_API35 -no-window -no-audio -no-boot-anim -gpu swiftshader_indirect`, wait for `sys.boot_completed`, then `ANDROID_SERIAL=emulator-5554 ./gradlew ...connectedFossDebugAndroidTest`. `ANDROID_SERIAL=emulator-5554 pnpm dev-android` installs there too. Set `CARGO_TARGET_DIR=/Users/chrox/dev/readest/target` from a worktree to reuse the main checkout's compiled deps (the tauri android build honours it).
- Run the plugin's instrumented tests from `src-tauri/gen/android`: `./gradlew :tauri-plugin-native-bridge:connectedFossDebugAndroidTest -Pandroid.testInstrumentationRunnerArguments.class=com.readest.native_bridge.ReadingWidgetStoreTest`. A fresh worktree lacks the autogenerated `tauri.settings.gradle`, `app/tauri.build.gradle.kts`, `app/tauri.properties`; copy them from the main checkout with the repo root path sed-rewritten.
- MIUI blocks every ADB install of a NEW/changed test APK with `INSTALL_FAILED_USER_RESTRICTED` and shows an "Install this app via USB?" dialog with a 10s Deny countdown. "Remember my choice" does not stick. Run gradle in the background and loop `uiautomator dump` + `input tap` on the "Install" node bounds (see [[feedback-always-verify-on-xiaomi]]).
