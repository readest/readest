`apps/readest-calibre-plugin/` implements #4863: calibre GUI plugin pushing selected books + metadata into the Readest cloud, modeled on BookFusion's plugin. MERGED to main via PR #4918 (2026-07-04, merge 6b403d019); packaged in releases as `Readest-<version>.calibre-plugin.zip` by release.yml's `build-calibre-plugin` job.

Design decisions and hard-won protocol facts:
- **Identity**: `Book.hash` = partial MD5 (KOReader algorithm; JS `1024 << -2` wraps to 0, so offsets are 0, 1024, 4096, ... 1024<<20). metaHash = `md5(NFC("title|authors,|ids,"))`, preferred id scheme uuid > calibre > isbn; Python impl verified byte-identical to `js-md5` output.
- **OPF embedding + uuid dedup** (v2, per maintainer request): metadata IS embedded into a temp copy at upload (`calibre.ebooks.metadata.meta.set_metadata` — deterministic for EPUB, writes custom columns as `calibre:user_metadata`). Dedup keys: calibre uuid in row `metadata.identifier` (survives byte changes) + `metadata.calibreSourceHash` = raw library-file partialMD5 (change detection, no local state; v1 rows fall back to `book_hash` which equals the raw hash). File changed → replace flow: upload new blob, push new row (carry-over) + tombstone old in one /sync POST, best-effort delete old cloud files. Metadata-only edit → row update, no re-upload (embedded OPF goes stale until next file upload).
- **POST /sync explicit-nulls absent fields** (transformBookToDB) — updates must carry over `uploadedAt`, `groupId/Name`, `progress`, `readingStatus*`, `coverHash` from the pulled server row (`wire.py::merge_for_push`); same lesson as koplugin syncbooks.lua.
- **Upload key** `Readest/Books/{hash}/{hash}.{ext}`; app's `{title}.{ext}` downloads resolve via download.ts hash+extension fallback. cover.png stores *original* bytes (app never converts formats, bookService.ts:568), so calibre's cover.jpg bytes upload as-is; coverHash = partialMD5 of those bytes.
- **OAuth from a non-app client works**: `{supabase}/auth/v1/authorize?provider=X&redirect_to=http://localhost:PORT` is whitelisted (readest-app's Flatpak/custom-OAuth production path uses it). Tokens arrive in the URL *fragment*; serve a page whose JS relays `location.hash` to `/callback?...` (tauri-plugin-oauth trick). Implemented in `oauth.py`.
- Pure modules (`api.py`, `wire.py`, `oauth.py`) are calibre-free; `make test` runs 56 unittests; `make zip` builds; smoke-test inside calibre with `calibre-debug -c` after `from calibre.customize.ui import find_plugin` (initializes the `calibre_plugins` namespace).

- **`uploaded_at` is NOT proof the blob exists** (2026-07-25 user report; MERGED #5325 cf4414f09). `books.uploaded_at` is the only "is it in the cloud" signal the plugin had, and three paths leave it stale-true: (1) **Manage Storage** file delete — `pages/api/storage/delete.ts` + `purge.ts` drop the object and the `files` row but never touch the `books` table; (2) deleting a book in the app with the **local** option — `services/cloudService.ts` only clears `uploadedAt` for `deleteAction` `cloud`/`both`; (3) signing out before the row change syncs. Consequence: `plan_push` picked `update` (row-only, no upload), and for a tombstoned-but-uploaded_at row `pick_server_row`'s resurrection path + `merge_for_push`'s `deletedAt = None` **republished the book with a `book_hash` whose file was gone** → visible in the library, `File not found` (download.ts 404s on the missing `files` row). Unrecoverable by re-pushing: the calibre file never changes, so `row_source_hash == source_hash` forever. Fix = verify against storage: `ReadestClient.list_all_files()` (paginate `/storage/list` by `totalPages`, NOT batch length — the endpoint pads pages with a book's sibling files) → `wire.cloud_book_hashes()` parses `{user_id}/Readest/Books/{hash}/{name}`, ignoring `cover.png`, because `files.book_hash` is only set when the uploader passed it → `plan_push(..., blob_present)` downgrades update/skip to `replace`. Listing failure ⇒ `cloud_hashes = None` ⇒ old trust-`uploaded_at` behavior (push still runs). Also fixed: `_remember` stored the sentinel `'uploaded_at': 'pushed'`, which `merge_for_push` fed to `iso_to_ms` → `ValueError` (now `ms_to_iso(record['uploadedAt'])`).
- **Status marks + perf** (MERGED #5332 20a073391). "Check Readest status" runs `plan_push` over the selection without uploading and writes calibre marks (`View.set_marked_ids`, labels `readest_synced|metadata|outdated|missing`), so `marked:readest_missing` selects what still needs a push; `merge_marks` replaces only `readest_` labels so hand-set marks survive; a push re-marks what it pushed. Calibre facts verified live: `set_marked_ids` does NOT fire `add_marked_listener`, so repaint needs `library_view.model().refresh_ids(ids)` (tolerates ids filtered out of the view); `marked_text_icon_for` renders any custom label. **Perf**: the upfront cost was `list_all_files` (22.4s for 1580 files) vs `pull_books` (3.2s) — `/storage/list` costs ~1s per request almost regardless of rows (1 file 0.93s, 100 files 1.23s). Fix = page 1 decides via `should_bulk_list(total_pages, len(book_ids))`, else per-book `list_files(hash)` cached per run; `plan_push` takes a callable checked LAST so new/replace never spends a request. 1 book 25.6s -> 4.8s. Server cap raised 100 -> 1000 (`MAX_PAGE_SIZE` in `pages/api/storage/list.ts`) — required batching the group-expansion `.in()` via `chunkIds` (100/batch) because Supabase renders it into the query string. `files.book_hash` is nullable but null rows are all Replicas, never book blobs. **Plugin version** now stamped from `apps/readest-app/package.json` by `sync_version.py` (`make zip` order-only prereq) + a test asserting no drift; the old `(0, 1, 0)` placeholder meant local builds installed under the wrong version.
- **Release packaging** (PR #4918): `build-calibre-plugin` job in release.yml mirrors the koplugin job; perl-stamps `PLUGIN_VERSION` from readest-app package.json, `make zip` → `Readest-<version>.calibre-plugin.zip` release asset. Committed version stays the (0, 1, 0) dev placeholder.
- **Pushing workflow files**: gh's OAuth token lacks `workflow` scope (HTTPS push of .github/workflows/* rejected); SSH push works (transient hangs — retry with ConnectTimeout/ServerAliveInterval).
