LocalSend support (send + receive books over LAN, wire-compatible with the LocalSend app). Branch `feat/localsend`, worktree `/Users/chrox/dev/readest-feat-localsend`. Spec + plan in `.agents/plans/2026-08-09-localsend-{design,implementation}.md`.

**Architecture:** Rust `src-tauri/src/localsend/` embeds upstream's own `localsend` crate (git dep pinned by rev, `features=["discovery"]`) — do NOT reimplement the protocol.

**The dep MUST come from our fork `readest/localsend` (branch `readest`), never `localsend/localsend` directly.** Cargo recursively inits+updates EVERY submodule of a git dependency — there is no `submodules = false` and no way to fetch only `packages/core`. Upstream's `.gitmodules` has one entry, `support/submodules/flutter` → the whole Flutter SDK, so a plain git dep balloons `~/.cargo/git/checkouts` to **552 MB** and the checked-out Flutter paths overrun Windows MAX_PATH: nightly died with `path too long ... BlueOrangeGradientSurfaceViewPlatformViewFactory.kt; class=Filesystem (30)` (run 31437261971, both Windows arches; macOS/Linux/Android passed). The fork's ONLY delta vs the pinned upstream rev is one line, `update = none`, on that submodule — cargo honors the submodule update strategy (`utils.rs:423`, verified in cargo 1.92 source) and prints `Skipping git submodule ... due to update strategy in .gitmodules`. Checkout drops to 39 MB. **When bumping the rev, rebase that one-commit patch onto the new upstream rev in the fork and re-pin** — repointing at upstream resurrects the Windows failure.

Do NOT reach for crates.io: `localsend` there is `wylited/localsend`, an unrelated third-party reimplementation (different module tree, zero features so `features=["discovery"]` fails to resolve, no TLS at all — its `fingerprint` is a random `Uuid::new_v4()`, pulls `native-dialog`, last published 2025-01). Upstream publishes no core crate under any name, so a git dep is inherent. Managed state `LocalSendState` (Discord-RPC pattern, no new plugin). Nine `localsend_*` commands + `localsend:*` events. Frontend `src/services/localsend/`, `src/store/localsendStore.ts`, `src/components/localsend/LocalSendManager.tsx` (mounted in library + reader pages). Receive → `ingestFile` (`forceCopy:true`) → `updateBooks`; staging dir `<appData>/localsend/inbox/`. Send entry: `sendNearby` context-menu id + multi-select `Nearby`, dispatched via `eventDispatcher.dispatch('localsend-send-books', {books})`.

**Interop gotchas (found in device testing, all fixed):**
- **mTLS kills the stable LocalSend app.** Upstream server's `mandatory_client_auth = web.is_none() && !web_upload`; the shipping Flutter app presents NO client cert, so with mandatory auth its TLS handshake is reset. Fix: pass `WebConfig { send:None, upload:true, i18n:default }` (an empty `WebConfig{send:None,upload:false}` does NOT work — `AppState.web` derives from `send` alone). Cert-less senders then fall back to body fingerprint like v2.1.
- **Tauri 2.11 ACL for app commands.** Since 2.11 app (non-plugin) commands resolve through the ACL. Every new command must be listed in THREE places: `build.rs` `AppManifest::commands()`, `capabilities/default.json`, `capabilities/webdriver-remote.json` — plus the generated `permissions/autogenerated/<cmd>.toml` files must be committed. Symptom of missing: `<cmd> not allowed. Command not found`.
- **Port fallback works:** Readest walks 53317→53327; when the LocalSend app owns 53317 Readest binds 53318 (verified). The chosen port travels in every announce/register DTO so it stays interoperable.
- **Same-host multicast:** upstream socket sets SO_REUSEPORT, so Readest + LocalSend app can co-join 224.0.0.167 on one Mac. Device picker refresh also runs an HTTP subnet scan whenever the list is empty (not only on iOS) to cover hosts multicast can't reach.

**Readest↔Readest discovery failure (MERGED #5626 on 2026-08-12, merge c5a2c7bc1; VERIFIED on macOS+Xiaomi hardware both directions; worktree and local branch removed, diagnostic examples deleted; fork commit 37219949 on `readest/localsend@readest` is rev-pinned — bumping the rev later means rebasing BOTH fork patches, `update = none` + `.no_proxy()`, onto the new upstream; fork clone lives at `~/dev/localsend`; upstream PR to localsend/localsend still worth filing):** Readest devices could not see each other while the LocalSend app saw everyone. THREE stacked causes, all confirmed on macOS+Xiaomi hardware:
1. **System proxy kills every HTTPS register on macOS.** Upstream client enables reqwest `system-proxy`; reqwest hardcodes `tls_info: false` on ALL proxied paths (CONNECT and SOCKS, `connect.rs`), and the protocol client needs the peer cert from TlsInfo, so with a macOS system proxy configured (127.0.0.1:8118/8119 here) every register dies with `Other(TLS info not found)` and the store stays EMPTY — announce answers, scans, everything. Env `NO_PROXY` does NOT bypass it; only `.no_proxy()` does. Fixed in fork commit on `readest/localsend` branch `readest` (`.no_proxy()` in `create_reqwest_client` — LAN-only traffic). Diagnose with a cargo example calling `LsHttpClientV2::register` directly; the release app has NO tracing subscriber so its errors are invisible.
2. **`ServerEventV2::Register` was dropped** in the event pump, so the ANNOUNCING side never learned who answered (the crate's `announce()` doc says to feed responders back via `add_device`; the Flutter app does — that is why LocalSend always saw Readest). Fixed: pump feeds `register_peer` → `add_device`, self-fingerprint guarded.
3. **Subnet scan probed only 53317** where a Readest peer never listens (Readest binds 53318+). Fixed: `SCAN_PORTS = [53317, FIRST_PORT=53318]`.
Note: transfers through the proxy WORKED (prepare-upload does not read TlsInfo) — only discovery broke, which is why 2026-08-09 send/receive testing passed. Same-host discovery Mac-Readest↔Mac-LocalSend-app stays impossible: scan skips own IP and the LocalSend app loses the UDP 53317 bind when Readest holds it. Multicast listener recipe: python SO_REUSEPORT socket joined to 224.0.0.167:53317 prints every announce (works alongside the apps).
