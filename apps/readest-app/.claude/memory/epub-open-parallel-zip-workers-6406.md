MERGED 2cd6915bd (2026-09-28); worktree + pr-6406 branches removed.

**zip.js `useWebWorkers` measured on the Xiaomi (8 cores): no gain, so it was dropped.** Main-thread long tasks were 0 ms both ways, so inflate never blocked the main thread. Section loads were unchanged, and doc open was 10-20 ms slower (probe + spawn). zip.js spawns up to `hardwareConcurrency` workers, each with its own wasm codec, and terminates them after 5 s idle. Don't re-propose workers without weak-device (e-ink) numbers.

**Parallel open path vs base (workers off):** docOpened -13..15%, initViewState -8..11%, 5-section jumps -8..18% on image-heavy EPUBs.

**Bench recipe:** a throwaway `console.log('[bench] ...')` in readerStore initViewState plus a localStorage switch, one `pnpm dev-android` build, then CDP `location.href='/reader?ids=<hash>'`. Measure first render by polling `foliate-view.renderer.getContents()`, and section jumps with `view.goTo(idx)` + the `load` event (it sometimes never fires → 15 s timeout, which happens in BOTH builds and is not a regression). CDP from Node needs `dangerouslyDisableSandbox` (loopback). Use `fetch('/json/list')`: the raw-socket discovery hung this time. See [[cdp-android-webview-profiling]].
