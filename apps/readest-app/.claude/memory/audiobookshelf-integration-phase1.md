**The `PlaybackSource` seam contract** (`src/services/playback/playbackSource.ts`): the shared interface `TTSController` and the new `AudiobookController` both implement, so `ttsMediaBridge` (lock screen, CarPlay, Android Auto, media keys) and `TTSSessionManager` (single-slot session ownership, sleep timer, headless persistence) don't fork per source type.
- Event names kept unchanged from the pre-existing TTS controller so `TTSController` "conforms structurally and unchanged apart from its `kind` tag": `'tts-state-change'` (detail `{ state: PlaybackState }`), `'tts-speak-mark'` (detail `TTSMark`, drives lock-screen metadata + position), `'tts-session-ended'` (detail `{ reason: 'ended' | 'error' }`), `'tts-highlight-mark'` (TTS-only; audiobooks never emit it). `PlaybackState` union: `'stopped' | 'playing' | 'paused' | 'stop-paused' | 'backward-paused' | 'forward-paused' | 'setrate-paused' | 'setvoice-paused'`.
- **`'stopped'` is transit-forbidden for audiobooks.** For TTS, `'stopped'` is a TRANSIT value hit on every paragraph advance and chapter transition; both consumers gate on `state === 'stopped' && !terminated` to filter that churn. For `AudiobookController`, `#setState('stopped')` is called at exactly one runtime site (inside `#finish()`, immediately paired with `#terminated = true`) plus the field initializer (`#state: PlaybackState = 'stopped'`, i.e. never-started) - it structurally cannot occur mid-playback the way TTS's can. This asymmetry was load-bearing in the pause-self-resume fix below.
- **Discriminator**: `readonly kind: 'tts' | 'audiobook'` is the sole discriminator on a live `PlaybackSource`, deliberately never `instanceof` (avoids pulling a whole controller module into every consumer's bundle). `TTSController.kind = 'tts' as const`, `AudiobookController.kind = 'audiobook' as const`. Narrowing helpers, both `(source: PlaybackSource | null | undefined) => T | null`: `asTTSController` in `src/services/tts/TTSSessionManager.ts` and `asAudiobookController` in `src/services/audiobook/AudiobookController.ts`.

**The `abs://` path scheme** (`src/utils/audiobook.ts`): `makeAbsFilePath(serverId, itemId) = 'abs://<serverId>/<itemId>'` (`ABS_FILE_SCHEME = 'abs://'`), with `parseAbsFilePath` as the reverse parser. `isAudiobook(book) = book.format === 'ABS'`. The book's `hash` (`src/services/audiobookshelf/librarySync.ts`) is `md5(filePath)` via `js-md5` (`src/utils/md5.ts`), i.e. `md5('abs://<serverId>/<itemId>')` - deterministic and reproducible on any device that syncs the same server+item, since `serverId` is itself `md5('abs:' + url.trim().toLowerCase())` (`src/services/sync/adapters/absServer.ts`). No separate source-map DB table (see deviations).

**Key invariants found in review:**
- **Live session aliasing in the stats gate** (`src/services/tts/TTSSessionManager.ts`, fixed in `1f4b555b7`): the `TtsStatsRecorder` must be constructed against the *live* `#session` object, not a spread copy. `adopt()` rewrites `session.bookKey` in place when the reader reattaches to a background session; a frozen copy would keep routing later progress/config lookups to the stale entry.
- **Mutate-before-save for library writes** (`src/services/audiobookshelf/librarySync.ts`, fixed in `d0e7feaab`): cover downloads must mutate `book.coverHash`/`book.coverImageUrl` in place *before* the upserts are merged into the store and `saveLibraryBooks` is called, never after. `applyOPDSCover`'s own docstring documents in-place mutation as only safe pre-save; mutating post-save skips the `coverThumbnails` cache and drops `coverHash` from that save pass.
- **`resolveUrl` must read the current token** (`src/services/audiobook/openAudiobook.ts`): the player's media-load `resolveUrl` reads `useABSServerStore.getState().getServer(server.id)` fresh on every call rather than closing over a captured server snapshot, so a track load issued after a 401-triggered token refresh (by this session or a concurrent periodic library sync) carries the rotated token. Deliberately bypasses `ABSClient#buildMediaUrl`, which reads off the client's constructor-captured server and would go stale across a long streaming session.
- **Pause self-resume regression class** (fixed in `92094dfc6`): `pause()` -> `AbsProgressSyncer`'s `onPause` hook -> `#cacheLocally` unconditionally `setLibrary()`s a new book object for the same hash -> the player route (subscribed to the whole library store, no selector) re-renders -> `book = getBookByHash(id)` is a new reference -> the session-open effect (deps `[book, libraryLoaded]`) re-runs -> the same-hash guard correctly skips a second claim, but the `.then()` was unconditionally reattached to the already-settled promise, and its `hadExistingSession` flag was frozen at claim time as `false`, so it called `controller.start()` again and resumed audio the user had just paused. Fixed by (1) keying the route's book lookup on the stable `id` string via local `useState` instead of subscribing to the whole store, and (2) checking `controller.state === 'stopped'` at `.then()`-fire time instead of trusting the frozen flag - safe specifically because of the transit-forbidden invariant above.

**Deviations from spec** (`.claude/plans/2026-08-18-audiobookshelf-phase1-plan.md`, agreed simplifications):
1. The spec's `(serverId, libraryItemId) -> book hash` SQLite source-map table is dropped; `hash = md5('abs://<serverId>/<itemId>')` is deterministic, so lookups parse the path instead of hitting a DB migration.
2. `PlaybackSource` ships with the *actual* member/event names the media bridge and session manager already consumed (`start`, `tts-state-change`, `tts-speak-mark`, ...) rather than the spec's idealized sketch (generic `state-change`, bare `pause`/`resume`/`stop`), so `TTSController` satisfies the seam without renames.

## ABS server info not syncing cross-device (2026-08-24, ROOT-CAUSED, awaiting deploy)

Setup on Xiaomi never appears on other devices: the DEPLOYED prod API (web.readest.com/api/sync/replicas) rejects `kind=abs_server` with 422 UNKNOWN_KIND — its `KIND_ALLOWLIST` predates the #5801 merge (probe: abs_server 422, opds_catalog 200 w/ rows). Device push is silently routed around (`unsupportedKinds`, session-scoped, `replicaSyncManager.ts`); the row never lands in the `replicas` table, so every device's pull returns 0 rows. ABS book stubs DO cross (legacy `/api/sync?type=books` channel) — books-without-server is the telltale signature. NO code fix needed (allowlist already on main); fix = web deploy, but migration 020 MUST be applied to prod first (see stat-pages memory) or stats pulls 500. After deploy the Xiaomi row self-heals: app restart clears unsupportedKinds and the 5-min ABS sync's `updateServer(lastSyncedAt)` (librarySync.ts:288) republishes. Credentials (tokens/password) still won't cross unless the user opts into the Credentials sync category — web will show the server but need a login.

**Orphan-tile fix (2026-08-24, MERGED #5841 `39275c986`, worktree removed).** (1) `isAbsBookOrphaned` in absServerStore + Bookshelf `visibleBooks` filter hides ABS books whose server row is absent/tombstoned from grid/groups/recent/search (rows stay in store and keep syncing; disabled servers still count as configured); (2) `backfillAbsCovers` in librarySync fetches missing covers UNAUTHENTICATED (cover endpoints public, itemId from filePath) before `syncAllAbsServers` in useABSSync, clone-then-replace so store books are never mutated in place. Web-verified: library 77 -> 28, orphan tiles gone. Suite 9938 pass + lint + format clean. Backfill not yet network-verified (needs a device with the server row).

**Missing covers on peers = same root cause, self-heals.** ABS covers never travel through Readest Cloud (audiobooks are fileless; transferManager.ts:154/184 returns null, nothing uploaded) — each device fetches covers DIRECTLY from the ABS server during its own `syncAbsServer` pass (`downloadAbsCover`; ABS cover endpoints are unauthenticated + CORS-open). A peer that adopted ABS books via the cloud books channel shows placeholder covers (local `/Readest/Books/<hash>/cover.png` 404s) until it can run its own ABS sync, which needs the server row + a login. Healing works because the cover loop's gate is `upserts` membership and cloud-adopted books ALWAYS reconcile as changed on first sync: `duration`/`episodeCount` are local-only Book fields (not cloud columns in transformBookToDB), undefined on the peer vs real values from ABS. LATENT coupling: cover backfill only runs for changed books — a book that reconciles unchanged with a missing cover.png never re-fetches it (masked today, would bite if duration/episodeCount ever become cloud columns).
