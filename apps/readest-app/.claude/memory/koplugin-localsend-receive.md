Branch `feat/koplugin-localsend`, worktree `/Users/chrox/dev/readest-feat-koplugin-localsend`. Spec+plan in `apps/readest-app/.agents/plans/2026-08-13-koplugin-localsend-{design,implementation}.md`. **Architecture:** a NEW standalone Rust cdylib crate `apps/readest.koplugin/native/localsend-ffi/` (its own Cargo.toml + `[workspace]`, NOT in the src-tauri workspace) wraps the SAME pinned `readest/localsend` fork rev as the app (`3721994985277e49e7e1ee4ed97601ad5405fc87`, `default-features=false, features=["discovery"]`). It is a receive-only port of `src-tauri/src/localsend/service.rs` + `identity.rs` (near-verbatim duplication is a deliberate scope decision — no shared crate). Exposes a poll-based C ABI (no callbacks — LuaJIT forbids foreign-thread callbacks into Lua): `ls_version`(→"1")/`ls_start`(json)/`ls_status`/`ls_poll_event`/`ls_accept`/`ls_decline`/`ls_stop`/`ls_string_free`. Codes OK=0 ERR_ARG=-1 ERR_STATE=-2 ERR_START=-3 ERR_PANIC=-100; every entry catch_unwind + poison-safe locks; global EVENTS FIFO drained by Lua. Event JSON: snake_case type tag + camelCase fields (`sessionId`,`fileName`,`totalSize`,`deviceModel`,`localIps`,`multicastError`). Server binds 53318-53327 (53317 left for the LocalSend app, UDP shared via SO_REUSEPORT); `WebConfig{send:None,upload:true}` for cert-less-sender fallback.

**Lua side:** `library/localsend_ffi.lua` = arch-keyed loader — `libNameFor` returns `liblocalsend-armv7.so` for Kindle+arm, `liblocalsend-arm64.dylib` for OSX+arm64+emulator, and **nil for everything else (Kobo Linux-arm is hard-float — MUST never get the softfp lib)**; ABI "1" checked via ls_version; unsupported/missing → menu shows "not available". `readest_localsend.lua` = module singleton (survives KOReader's per-context plugin re-instantiation; `init` re-attaches the poll loop), 0.5s `UIManager:scheduleIn` poll tick, ConfirmBox accept/decline, sender-abort dismisses the open dialog, end-of-session summary. Received files register via `plugin:addToReadest(path,{silent=true})` (opts.silent added in main.lua) as local-only rows — NO cloud upload. `dataDir = DataStorage:getSettingsDir().."/readest-localsend"` (outside plugin dir so self-update keeps the pinned identity). `library_download_dir` unset state is `nil` never `""` (only writer is libraryviewmenu PathChooser).

**Cross-compile (`scripts/build-localsend-libs.mjs`, `--only armv7|arm64-mac`):** arm64-mac = native `cargo build`; armv7 = `cargo zigbuild --target armv7-unknown-linux-gnueabi.<glibc>` (zig linker; needs `brew install zig` + `cargo install cargo-zigbuild`). **KINDLE_GLIBC='2.12'** — verified empirically: KOReader's own koreader-kindle-v2026.07.1 binaries (libzmq.so.5) floor at GLIBC_2.12; luajit alone reads a uselessly-low 2.4 so check ALL shipped .so. **Kindle target is armv7 SOFT-FLOAT only** (matches the universal `koreader-kindle` build, runs on every model; user chose softfp-only 2026-08-13, kindlehf/hardfloat explicitly out of scope). ELF acceptance gate: ELF32 ARM, header `soft-float ABI`, `Tag_ABI_VFP_args` ABSENT (a VFP-registers value = hard-float = FAIL), max GLIBC ≤ floor. Gotcha: the availability probe must be `cargo-zigbuild --version` — `cargo zigbuild --version` ALWAYS exits 2 (cargo forwards it as a subcommand with no --version).

**Packaging:** `libs/` is gitignored (built artifacts, ~5MB each); `native/` is committed but excluded from the plugin zip (build-koplugin.mjs + release.yml both list `native/*` alongside scripts/docs/spec; release.yml gained a CI step building the armv7 lib via `pip3 install --break-system-packages ziglang cargo-zigbuild` before zipping — that pip3 path is UNTESTED e2e). Self-update ships whole zips so libs travel automatically. CI builds armv7 only; the arm64 dylib is a local dev artifact for the emulator.

**Security fix during review:** peer-supplied `file.file_name` was joined into the write path unsanitized (remote arbitrary-file-write; a peer named `../../../../etc/init.d/rcS` escapes, and KOReader often runs as root). Fixed with `safe_file_name` (crate `sanitize_with(Rules::Universal)` on the last path segment, empty→`"received.bin"`). **The SAME hole still exists in the shipped Tauri app** at `apps/readest-app/src-tauri/src/localsend/service.rs` `handle_file_upload` → `unique_path(dir, &file.file_name)` — needs its own fix/PR on main, out of this branch's scope.

**Kobo hard-float added (2026-08-13, user requested mid-build):** all Kobo builds (kobo/kobov4/kobov5) are hard-float `gnueabihf` per KOReader `base/Makefile.defs -mfloat-abi=hard`; Kindle stays soft-float. Added `armv7hf` build target (`armv7-unknown-linux-gnueabihf`, KOBO_GLIBC='2.12' from koreader-kobo-v2026.07.1 libzmq.so.5) → `liblocalsend-armv7hf.so` (ELF32 ARM, header `hard-float ABI`, `Tag_ABI_VFP_args: VFP registers` PRESENT — INVERSE of the Kindle check). `libNameFor` keys `Device:isKobo()`→armv7hf, `isKindle()`→armv7 (softfp); the two ABIs are NOT interchangeable (glibc ARM loader rejects float-ABI mismatch at dlopen), so device-class keying, NO try-load fallback. Release CI builds `--only armv7` AND `--only armv7hf`. PocketBook/Cervantes are also softfp gnueabi (would be ABI-compatible) but NOT wired (libNameFor returns nil for non-Kindle-non-Kobo); kindle-legacy is armv6 (our armv7-a code would SIGILL) — not offered.

**ANDROID IS IMPOSSIBLE with this architecture — proven on real hardware (ONYX Leaf5, arm64, Android 13, KOReader v2026.07.1, 2026-08-13).** A throwaway `ffiprobe.koplugin` (minimal Bionic arm64 .so + one exported symbol, built via NDK r28c) `ffi.load`ed from BOTH the plugin dir AND a data-dir copy. BOTH fail: `dlopen failed: library "..." is not accessible for the namespace "classloader-namespace"` (dlopened by the APK's `lib/arm64/libluajit.so`). This is Android's linker classloader-namespace restriction (Android 7+): dlopen only permits the APK's own extracted `/data/app/.../lib/<abi>/` + system paths; ANY `.so` on external storage is rejected regardless of file perms/exec bits — it is NOT a noexec/EACCES problem. The data-dir copy mitigation ALSO fails because this KOReader build's `DataStorage:getDataDir()` is external storage (`/storage/emulated/0/koreader/`), still outside the namespace. Only path to Android would be bundling the lib into KOReader's APK jniLibs (upstream, out of scope). **Android users use the native Readest Android app instead. Do not revisit unless KOReader upstream ships the lib in-APK.** Evidence: session scratchpad `leaf5-ffiprobe-result.png` + logcat.

**FINAL WHOLE-BRANCH REVIEW (opus) found 2 merge-blockers the per-task reviews missed — both FIXED:** (1) `readest_localsend.lua` `error`/`started` handlers used `_` as the first param, SHADOWING the module `local _ = require("readest_i18n")`; the error handler's `_(...)` call crashed KOReader on the ls_start-failure path (not inside a pcall). Fixed: rename param `_self`; error handler now also calls `stopService()` so a failed start resets client state; spec now INVOKES the real handlers. (2) First `ls_start` ran RSA-2048 keygen SYNCHRONOUSLY on KOReader's single UI thread via `rt.block_on` -> multi-second frozen e-ink screen, no feedback. **Fixed by making `ls_start` non-blocking:** it now spawns a worker OS thread owning the tokio runtime and returns immediately (LuaJIT is single-threaded, so ONLY a Rust-side thread can keep the UI live). New `LiveStatus{Starting,Running,Failed}` behind a shared mutex; `ls_status` gained a `starting` bool; `ls_stop` signals+detaches (no join, no UI stall); `service::accept/decline` re-typed to take the map Arcs directly since `Running` no longer holds the `Service` (the Arcs ARE the live server's maps — verified). Follow-on concurrency-review fixes: identity.pem EEXIST race (concurrent keygen -> loser adopts winner's cert on `AlreadyExists`, unix-only cfg path); failed-start self-heals on next `ls_start` (drops stale `Failed` STATE); `run_worker` under `catch_unwind`; `Started` event emitted only AFTER `Running` set. Also: `onResume` restarts the service; ConfirmBox `flush_events_on_show=true` (stray page-turn tap no longer auto-declines an incoming transfer); empty-string download-dir fallback; new `koplugin_rust_lint` PR CI job (crate had ZERO PR CI before — pull-request.yml rust job was src-tauri-only). `Event::Error` is emitted ONLY on start-failure paths (lib.rs), NEVER by the steady-state service.rs pump — so `error`->stopService can't tear down a running service.
